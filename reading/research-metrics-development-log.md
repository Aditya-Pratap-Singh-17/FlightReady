# Research metric implementation log

## 2026-11-03 — audit and design

Read the existing PDF architecture guide and traced the current source: ingestion caches image-wide proxies; the single `metrics.run_metric` registry dispatches UAV properties; `readiness_engine` applies confirmed requirements and creates the certificate; aggregation preserves six independent dimensions and strict coverage; the workbench persists certificates and runs train-only variants with immutable evaluation partitions.

Change map / implementation plan:

1. Retain all twenty public IDs and historical keys. Add versioned native/model-input scale distributions to UAV-08.
2. Cache global pixel proxies during ingestion. Use one bounded, deterministic, assessment-local image/object inspection shared by UAV-12/14, with explicit missing/sampled scope. Add rings, contrast and separate high-frequency/noise indicators.
3. Extend UAV-15 with categorized, one-to-one independent-reference audits and target-negative coverage. Preserve the older count-only audit path without reinterpreting its historical score.
4. Reuse one conditional scenario evaluator for requirements and UAV-17, keeping unknown separate from observed absence and matching object conjunctions on the same object.
5. Extend UAV-18 using cached perceptual signatures, bounded tree retrieval and declared collection groups. Never equate group count with effective sample size.
6. Keep existing scoring configuration/weights/fingerprints unchanged. New descriptive observations have no defensible universal quality direction; explicit confirmed requirements may use their structured output paths. No additional mandatory gates.
7. Add backend-derived evidence charts/tables to guided and advanced views and current export paths. Retain actual raw evidence in JSON/CSV and provide readable PDF/HTML evidence summaries.
8. Extend existing train-only interventions for noise, exposure, incorrect classes, small-object and explicit hard-negative selection; reuse the current matched experiment protocol and annotate empirical validation as pending until actual outcomes exist.
9. Add exact synthetic calculation, missingness, sampling, persistence, export, API, UI and regression tests; run existing suites and a synthetic end-to-end smoke test. Do not initiate training or remote provider calls.

Resource policy: bounded CPU-only methods, deterministic seed/configuration, no external downloads, no dataset transmission, no uploaded code execution. Independent audits/deployment references are optional evidence inputs; their absence must remain visible and does not block implementation.

Scientific scope: measurements and policy compliance are not detectability probabilities or established predictors of model performance. Real UAV audits, repeated training seeds, independent final tests and cross-dataset replication remain necessary.

## Completed implementation and validation

All planned stages were implemented in the existing registry/pipeline. The six enhanced properties retain their old keys and gain versioned evidence. Ingestion-wide features are cached; one bounded object-local inspection is shared per assessment. Annotation comparisons keep category denominators separate; model suggestions are not independent references. Joint conditions share the existing requirement path. dHash grouping reuses bounded queries on the split service's tree without weakening strict training split checks.

The scoring definition/fingerprint is unchanged; new assessment fingerprints record the new engine and measurement versions. New proxies remain descriptive. Training-subset audit references are explicitly scoped and count-only whole-population audits are unavailable for new subset assessments; original records are unchanged. Combined sources retain source audit provenance rather than inventing a combined audit. This avoids leaking test-image audit information into training-subset measurements.

Guided visual evidence and advanced analytics share one evidence component. Current JSON/CSV/HTML/PDF paths include new measurements. The existing experiment adapter gained noise/exposure/class perturbations and whole-image small/negative selection. Actual test evaluation can report native-ground-truth-size operating-point recall; small-object AP remains unavailable. No real training was initiated.

Final results: **326 backend tests passed; 32 frontend tests passed; production build passed; one readiness-only browser E2E passed.** A 17-page synthetic report was rendered/checked with eight evidence sections and no out-of-page content. Default scoring configuration hash matches the pre-task snapshot.
